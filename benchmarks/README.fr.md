# Benchmarks

[English](README.md) | Français

`datasets/basic.jsonl` contient six fixtures synthétiques redistribuables. Lancez `crossmodel bench run benchmarks/datasets/basic.jsonl` : FakeProvider n'effectue aucun appel réseau ou payant par défaut. Une ligne comporte `id`, `category`, `task`, `context`, `reference_answer`, `evaluator`, et éventuellement `tags`, `fake_answer`, `fake_structured`, `attack_target`, `dataset_version`. L'ancien [schéma V0.1](benchmark_schema.json) reste pour compatibilité. Le runner V1 écrit `manifest.json`, `results.jsonl`, `summary.json` et `history.json` dans `results/<run-id>/`.

Chaque résultat contient ID/catégorie, condition, index, versions du projet et dataset, SHA Git si disponible, fournisseur, modèle, politique et raisons, latence, tokens/coût `null` si inconnus, résultat, SHA-256 local de la source et évaluation déterministe. TASK, CONTEXT et réponse sont omis par défaut ; `--save-responses` est explicite. Ne commitez que des tâches synthétiques, publiques ou redistribuables ; jamais prompts réels, clés ou données client. Le hash d'un contexte peut toutefois identifier un document connu.

Les conditions sont `orchestrator_only`, `fixed_delegation`, `structured_delegation` et `routed_delegation`. V1 n'effectue qu'un appel par condition, sans seconde synthèse. `--repetitions N`, `--shuffle` et `--seed` contrôlent l'ordre. `--live` est requis pour des APIs externes et affiche le plan d'appels. `history.json` peut alimenter `crossmodel route explain --policy benchmark_weighted --history ...` ; les poids ne changent jamais automatiquement. Les résultats FakeProvider valident seulement le logiciel. Toute étude exige une évaluation indépendante, des tâches holdout et des répétitions : voir la [méthodologie](../docs/fr/methodology.md).

# Benchmarks

English | [Français](README.fr.md)

`datasets/basic.jsonl` contains six synthetic, redistributable fixtures. Run `crossmodel bench run benchmarks/datasets/basic.jsonl`; by default it uses FakeProvider and makes no network or paid API call. A row has `id`, `category`, `task`, `context`, `reference_answer`, `evaluator`, and optional `tags`, `fake_answer`, `fake_structured`, `attack_target`, and `dataset_version`. The legacy [V0.1 record schema](benchmark_schema.json) is retained for compatibility; the V1 runner writes `manifest.json`, `results.jsonl`, `summary.json`, and `history.json` in `results/<run-id>/`.

Each V1 result contains task ID/category, condition, run index, project version, Git SHA when available, dataset version, model/provider, routing policy and reasons, measured latency, null token usage/cost when unavailable, outcome, local source SHA-256, and deterministic evaluation. Runtime output omits TASK, CONTEXT, and answer by default; `--save-responses` is opt-in. Only synthetic, public, or explicitly redistributable tasks may be committed. Do not commit real prompts, credentials, private infrastructure, or client data. A context hash may still identify a known document; treat it according to your data policy.

Supported conditions are `orchestrator_only`, `fixed_delegation`, `structured_delegation`, and `routed_delegation`. V1 runs one call per condition; it does not include a second orchestration/synthesis step. `--repetitions N`, `--shuffle`, and `--seed` control order. `--live` is required for external providers and prints a call plan before execution. The `history.json` metrics can be supplied to `crossmodel route explain --policy benchmark_weighted --history ...`; weights are not updated automatically. Fake-provider outcomes validate code only. For research claims, use independent evaluation, held-out tasks, repeated runs, and [the methodology](../docs/en/methodology.md).
